# Domain docs

This repository uses one root `GLOSSARY.md` and one `docs/adr/` directory.

Before exploring an area, read the root glossary and any ADRs that apply.
Proceed silently if those files are absent. The `domain-modeling` skill
creates them as terms and decisions are settled.

Use glossary terms in tickets, proposals, and tests. If a proposal conflicts
with an ADR, cite the decision and explain why it should be reopened.
